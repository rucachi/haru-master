## 🎯 [복사하여 사용할 프롬프트 본문]

아래 박스 안의 내용을 그대로 복사하거나 **"Q.md 참고해서 이번 주 문제 생성해줘"**라고 요청하시면 됩니다.

```markdown
[지시사항: 하루마스터 주간 신규 문제 생성 및 자동 배포]

`study_data/Q.md`의 표준 출제 가이드라인과 현재 진도 현황을 바탕으로, 이번 주 신규 문제를 생성하고 감사·검수 완료 후 Cloud Firestore 및 학생 웹에 배포해줘.

1. 출제 대상 및 문항 수:
   - 나경이 (중3): 수학 30, 과학 30, 사회 30, 역사 30, 영어 10, 국어 10 (총 140문항)
   - 차혜 (중1): 수학 30, 과학 30, 사회 30, 영어 10, 국어 10 (총 110문항)
   - 총 250문항 신규 생성

2. 출제 시작 지점:
   - 이전 출제 완료 단원(중간고사 범위)의 '다음 단원(기말/후속 진도)'부터 시작할 것.
   - [출제 진도표] 섹션의 '다음 출제 시작 단원'을 반드시 따를 것.

3. 난이도 및 유형 배분:
   - 쉬움 30%, 보통 40%, 어려움 30% 엄격 준수.
   - 국어/영어: 지문 독해 50%, 문법 및 어휘 50%.
   - ★ [필수 독해 표준] 국어와 영어 독해 문제는 반드시 "긴 지문 1개당 2~3개 하위 연계 문항(세트형)"으로 출제할 것.
     (예: 문항 1 - 주제/중심 내용, 문항 2 - 세부 내용 일치/불일치, 문항 3 - 어휘/문맥 추론)
   - 수학/과학: 공식 계산, 개념 적용, SVG 다이어그램 자료 해석 고르게 포함.

4. 절대 규칙 (Zero-Hallucination & No-Duplicate):
   - 5지선다 선택지 5개 간 중복(Duplicate) 절대 불가 (동일 숫자, 중복 선택지 엄금).
   - 정답 인덱스(1~5)와 실제 선택지 내용, 해설(explanation) 100% 일치할 것.
   - 수학/과학 공식과 역사적 팩트 무결성 검증.

5. 실행 및 배포 파이프라인:
   - Python 생성 스크립트 작성 및 자동 감사(audit) 수행 후 JSON 업데이트
   - `study_data/nakyeong/` 및 `study_data/chahye/` 누적 데이터셋에 병합
   - Cloud Firestore 연동 및 GitHub main 브랜치 커밋 & 푸시 완료 후 결과 보고
```

## 📊 2. 문항 수 및 난이도 배분 기준 (Quota & Difficulty)

- **과목별 출제 문항 수**:
  - 수학, 과학, 사회, 역사: **각 30문항**
  - 국어, 영어: **각 10문항** (독해 5문항 + 문법/어휘 5문항)
  - 주간 총 생성 문항: **나경이 140문항 + 차혜 110문항 = 총 250문항**

- **난이도 3단계 비율 (30 : 40 : 30)**:
  - **쉬움 (30%)**: 핵심 용어 정의, 기본 공식 대입, 직관적인 개념 확인 문항
  - **보통 (40%)**: 교과서 예제 수준, 조건이 2개 결합된 계산/추론, 단원 표준 기출 문항
  - **어려움 (30%)**: 복합 개념 적용, 함정 선지 포함, 자료(SVG 그래프/도형) 심층 해석 문항

### 📖 [핵심 표준] 국어·영어 독해 세트형 복합 지문 체계 (1지문 2~3하위문항)
아이들의 문해력과 심층 독해 능력을 향상시키기 위해, **독해 문항은 단일 파편화된 문항이 아닌 1개의 장문 지문에 2~3개의 하위 문항이 유기적으로 연결된 세트 구조**를 표준으로 합니다.

1. **지문 구성 (Passage Structure)**:
   - 분량: 200~450자 (영어는 60~130단어) 내외의 완성도 높은 단락.
   - 주제: 교과서 진도 핵심 제재 (문학, 과학, 환경, 역사, 인공지능, 일상 윤리 등).
2. **하위 문항 다각화 (Sub-item Diversity)**:
   - **문항 1 (거시적 독해)**: 글의 중심 생각, 주제, 제목, 글쓴이의 의도/태도 파악.
   - **문항 2 (미시적 사실 확인)**: 본문 내용과의 일치/불일치, 인과관계, 핵심 세부 정보 파악.
   - **문항 3 (심층 추론 및 적용)**: 핵심 어휘의 문맥적 의미, 빈칸 추론, 실생활 적용 및 반응 평가.
3. **50문항 사전 비축 규격 (20개 복합 지문)**:
   - 10개 지문 × 3개 하위 문항 = 30문항
   - 10개 지문 × 2개 하위 문항 = 20문항
   - **총 50문항 풀 세트** 완성.
   - 현황: 나경이 국어 50 + 영어 50 + 차혜 국어 50 + 영어 50 = **총 200문항 사전 비축 완비**.

## 🔍 3. 문제 출제 시 반드시 고려해야 할 5대 원칙 (Quality Checklist)

### ① 무결성 및 할루시네이션 방지 (Zero-Hallucination & No-Duplicate)
- **5지선다 선택지 중복 절대 금지**:
  - 파이썬 스크립트 작성 시 `assert len(set(options)) == 5` 검증 코드를 필수 삽입할 것.
  - 모듈로 연산(`i % n`)으로 선택지를 만들 때 수치가 겹치지 않도록 완전히 분리된 구간(Disjoint Range) 설정.
- **정답-해설 일치**:
  - `options[correct_answer - 1]` 텍스트가 `explanation` 해설의 결론과 100% 일치해야 함.
  - 수학 특수각($\tan 60^\circ = \sqrt{3}$ 등) 및 과학 법칙 수치 계산 오류 원천 차단.

### ② 시각 자료(SVG 다이어그램) 표준 규격
- 수학의 입체도형(원뿔, 구, 기둥 전개도)이나 과학의 파동 그래프, 사회의 정치 과정 모형도는 **인라인 SVG Data URI**로 생성:
  - 배경: 흰색(`fill="#ffffff"`), 둥근 모서리(`rx="8"`)
  - 해상도: `viewBox="0 0 320 200"`, 태블릿 화면에 선명하게 렌더링.

### ③ 지문(Passage) 분리 및 복합 세트형(1지문 2~3문항) 출제 원칙
- 국어·영어 및 탐구 영역의 장문 지문은 반드시 `passage` 필드에 분리할 것.
- **연계 문항 규칙**: 동일한 지문을 공유하는 하위 문항들은 각 문항의 `passage`에 지문 원문을 온전히 포함하여, 태블릿 웹 뷰에서 지문 박스와 개별 발문이 직관적으로 렌더링되도록 함.
- 줄바꿈과 문단 구분이 살아있어야 하며, 인공지능 윤리, 환경 보호, 과학 기술, 문학 수필 등 **중학생 수준에 맞는 양질의 교육적 지문** 채택.

### ④ 수식 표기 규격 (KaTeX)
- 인라인 수식: `$ ... $` (예: `$S = \frac{1}{2}rl$`, `$\sin 30^\circ$`)
- 화학식 및 단위: `$\text{cm}^2$`, `$\text{J}$`, `$\text{m/s}^2$` 형태로 단위를 텍스트 처리하여 렌더링 품질 극대화.

### ⑤ 실생활 연계 및 동기 부여 (Contextualization)
- 아이들의 일상(학교 축제, S펜 태블릿 필기, 반려동물, 용돈 관리, 날씨 등)을 지문이나 문제 상황에 자연스럽게 접목하여 학습 흥미 유도.

## ⚡ 4. 자동 업데이트 파이프라인 (Execution Pipeline)

문제가 생성되면 AI는 다음 절차를 단절 없이 순차 수행합니다:

```mermaid
graph TD
    A["1. 프롬프트 확인 및 단원 선정"] --> B["2. build_weekly_questions.py 생성 및 감사 (Audit)"]
    B --> C["3. study_data JSON 데이터셋에 누적 병합 (1060문항+)"]
    C --> D["4. Firebase Realtime DB 동기화 실행"]
    D --> E["5. Git commit & push (GitHub Pages 웹 자동 갱신)"]
```

1. **JSON 데이터 누적 병합**: 기존 데이터셋에 신규 생성 문항을 병합하여 문제 은행 확장 (현재 1,060문항 완비).
2. **Cloud Firestore 동기화**: 검수 완료 JSON만 Firebase CLI 또는 승인된 동기화 경로로 업로드.
3. **깃 배포**: `git add`, `git commit`, `git push origin main`으로 GitHub Pages 실시간 배포 완료.

## 🧪 5. 고도화된 생성·감사·검수 운영 계획

문항 생성은 한 번에 대량 배포하지 않고 다음 게이트를 순서대로 통과해야 한다.

### Gate 0. 출제 설계

- 대상 학년, 과목, 교과서, 단원, 성취기준, 문항 수를 먼저 고정한다.
- 기존 데이터의 단원별 문항 수와 중복 발문을 먼저 조회한다.
- 신규 문항은 `question_id`, `chapter`, `difficulty`, `origin`, `review_status`를 반드시 포함한다.
- 자체 생성 문항은 `origin: "generated"`, 외부 허용 자료를 변형한 문항은 `origin: "adapted"`와 출처·라이선스를 기록한다.

### Gate 1. 자동 구조 감사

다음 조건을 하나라도 위반하면 JSON 병합과 배포를 중단한다.

- `question_id` 전역 중복 없음
- 문제 본문 중복 및 정규화 유사 중복 목록 확인
- 보기 정확히 5개, 보기 간 중복 없음
- 정답 번호가 보기 범위 안에 있음
- 해설·단원·난이도·생성 출처 필드 존재
- 국어·영어 지문은 2~3개 하위 문항 단위의 세트 구조
- 수학·과학 SVG는 `viewBox="0 0 320 200"`와 흰 배경을 사용
- LaTeX 괄호·달러 기호 쌍 정상
- 난이도 비율이 목표치에서 ±2% 이내

### Gate 2. 내용 검수

- 정답 선택지와 해설의 결론을 사람이 확인한다.
- 수학 계산은 독립 계산으로 재검산한다.
- 과학·사회·역사 사실은 교과서 또는 공신력 있는 기준 자료와 대조한다.
- 국어·영어 지문은 발문이 지문만으로 해결되는지 확인한다.
- 기존 문항과 같은 개념을 평가하더라도 숫자·조건·보기·풀이가 독립적인지 확인한다.
- 검수 완료 문항만 `review_status: "human_verified"`로 변경한다.

### Gate 3. 병합·배포

- 기존 원본 데이터는 백업하고, 감사 보고서와 신규 JSON을 함께 보관한다.
- 검수 대기 문항은 학생 출제 풀에 포함하지 않는다.
- `scripts/test_verify_dataset.py`와 감사 스크립트를 모두 통과시킨다.
- Cloud Firestore 배포 성공을 확인한 뒤 GitHub Pages를 배포한다.
- 배포 후 나경·차혜 화면에서 문제 로딩, 채점, SRS 기록을 브라우저로 확인한다.
